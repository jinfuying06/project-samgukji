# Codex ↔ Claude Code Handoff Playbook

## 원칙

모델 간 인계는 “이전 대화 요약”이 아니라 **입력·변경·검증·잔여 위험 계약**입니다.

## 보내는 쪽

1. 범위 밖 변경이 없는지 확인합니다.
2. 검증 명령을 실행합니다.
3. `LAST_HANDOFF.md`에 실제 결과를 기록합니다.
4. 중요한 결정은 `DECISIONS.md` 또는 ADR에 기록합니다.
5. 다음 역할이 필요한 파일을 구체적으로 적습니다.

## 받는 쪽

1. handoff의 주장을 믿기 전에 변경 파일과 검증 결과를 확인합니다.
2. 승인된 계약과 충돌하면 작업을 멈추고 blocker로 기록합니다.
3. 이전 모델의 숨은 의도를 추측하지 않습니다.
4. 부분 완료를 완료로 확대 해석하지 않습니다.

## 추천 교차 사용

| 작성 | 독립 검토 |
| --- | --- |
| Claude Code: 연구·제품 초안 | Codex: 스키마 일관성·테스트 가능성 |
| Codex: 파이프라인·API·UI | Claude Code: 요구 누락·서사/UX·방법론 |
| 어느 쪽이든: LLM 프롬프트 | 다른 쪽: source-mode leakage·grounding eval |
| 어느 쪽이든: 기본 점수 | 다른 쪽 + 사람: 공식·가중치·편향 검토 |

## 인계 프롬프트

```text
저장소의 루트 지침, 도메인 오버라이드, CURRENT_TASK.md,
LAST_HANDOFF.md, DECISIONS.md를 먼저 읽어.
이전 모델의 설명을 가정하지 말고 변경 파일과 검증 근거를 확인해.
너의 역할 파일에 지정된 범위만 수행하고 인계 문서를 갱신해.
```
