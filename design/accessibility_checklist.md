# Accessibility Checklist — S3 (적벽대전 Vertical Slice, Hybrid)

Status values: `PASS`, `PARTIAL`, `FAIL`, `N/A`, `NOT_TESTED`. `PARTIAL` means real testing happened and found no violation in what it covered, but the row's full scope wasn't exercised — read the Evidence/issue column for exactly what was and wasn't covered before trusting a `PARTIAL` row.

**What actually changed this pass (2026-09-19):** a real-browser automated suite now exists — `tests/e2e/accessibility.spec.ts` (`npm run test:e2e`, Playwright + `@axe-core/playwright`, real Chromium, real backend, real imported data) — going beyond the `jest-axe`/jsdom component tests (`tests/components/*`), which cannot evaluate real layout, computed contrast, or true focus/viewport behavior. Running it against the live app found and fixed **three real bugs**, all logged in `handoffs/DECISIONS.md`:
- **D-033**: `QuestCard` rendered a clickable button only for the counter-evidence item, never for the required-layer evidence (`HB-J54-P2`) — a real user could never satisfy the completion gate through the actual UI.
- **D-034**: 6 of the design's color tokens failed WCAG AA 4.5:1 against the actual self-tinted badge/chip backgrounds they render on in this app (`color-mix(in srgb, var(--token) N%, ...)`), as low as 3.74:1 — not caught by checking tokens against the flat page background alone. Also found 5 of 6 screens had no `<h1>` or skipped a heading level once one was added.
- **D-035**: `QuestCard`'s "완료" button did nothing when clicked, even once enabled — a separate, differently-labeled "퀴즈로 이동" button (not in `component_spec.md`) was silently doing the real completion work instead.

**Still not covered by anything in this repo, by design:** real assistive-technology testing (an actual screen reader, a human using one) has never been done. No automated tool substitutes for that, and no row below should be read as covering it — that gap stays open until a human actually does it.

## Notes for whoever runs this checklist next

- Re-run `npm run test:e2e` (needs the backend already running on :8000 with real imported data — see `app/backend/README.md`) after any change to `src/theme/tokens.css`, screen headings, or `QuestCard`/`AIAnswerPanel` — those are exactly what D-033/D-034/D-035 broke silently before this pass.
- A `PARTIAL` row is not a `PASS` waiting to be relabeled — it names a real, specific gap. Close the gap by extending `tests/e2e/accessibility.spec.ts`, not by changing the status without new evidence.
- Real assistive-technology testing (a human, an actual screen reader) remains the biggest open gap and cannot be done by an agent. Do not let a `PASS`/`PARTIAL` here be read as covering it.
